# T13 — диференційна перевірка 27 API-маршрутів: Node (pinned image) ↔ Rust

**Scope:** `deploy/scripts/api_parity_check.py` (новий хостовий скрипт) + цей
запис. Жодного файлу в `server/src`, `server/tests`, `server/tests/fixtures/`,
`server/Cargo.*`, `deploy/scripts/capture_api_golden.py`, `deploy/scripts/make_synthetic_db.py`,
`src/` не змінено; `capture_api_golden.py` використано лише як **read-only
імпорт** (порядок маршрутів, cookie/TOTP-потік, нормалізація, механіка
контейнера) і не редагувалося. Обсяг скрипта: 528 рядків (python3 stdlib).

## Мета (plan §3.7, §13.3 T13)

Довести 27/27 паритет legacy API: живий **pinned Node image** проти **Rust
release-бінарника** на двох **байт-ідентичних** копіях синтетичної v7 БД,
той самий фіксований потік 1..27, нормалізація R1–R9, `device_access`
виключено з контракту.

## Як працює скрипт

1. **Дві копії БД** — двічі `python3 deploy/scripts/make_synthetic_db.py
   --out <tmp>/database.sqlite --summary-json` (лише temp-каталоги; ні
   прод, ні стейджинг скрипт не згадує й не відкриває). Перевірки перед
   стартом: `failures=[]`, `schema_version=7`, `journal_mode=delete`,
   summary-и рівні (окрім шляху), `sha256(db1)==sha256(db2)` →
   `content_sha256=6745537d86f2343ec76ad1eca6a8162cdebd5680428f7782734f3f612abcfbc1`,
   `byte-identical=yes`.
2. **Node stand** — `docker create/start` pinned image
   `ghcr.io/meow-meow-ltd/lampa-source@sha256:d678c142…21add7`
   (`-p 127.0.0.1:9122:3000 -e DB_PATH=/data/database.sqlite -e HOST/0.0.0.0
   -e PORT=3000 -e TOTP_SECRET=<той самий> -v <db1dir>:/data`), readiness
   `GET /` → 200 (≤60 с). Скрипт ніколи не робить `pull` (fail-closed, як у T03).
3. **Rust stand** — release-бінарник `.cargo-target/release/lampa-server`,
   env `HOST=127.0.0.1 PORT=9123 DATABASE_URL=sqlite:<db2>?mode=rw
   TOTP_SECRET=<той самий> DEVICE_LEGACY_COOKIE=1 RUST_LOG=info`, readiness
   `GET /readyz` → 200 (≤30 с; лог — у temp-файл). Господар не має Rust
   тулчейна: **відсутній або застарілий бінарник → exit 2 + підказка**
   з builder-рецептом
   (`docker run … lampa-rust-builder:1.100.0 bash -c 'cargo build --release --locked --offline'`).
4. **Потік 1..27** — точна копія T03: setup `POST /admin/login` → cookie
   `auth_token` для маршрутів 02–06; `01 POST /api/pin/verify` (свіжий
   TOTP, однаковий секрет у обох stand-ів) → `device_token` → cookie
   `device_token` для 07–25; 26/27 без кук; фіксований UA
   `lampa-golden/1.0`, `profile: 1` на 13–23, ті самі тіла запитів.
5. **Порівняння** по кожному маршруту: статус (обидва 200), `content-type`,
   `cache-control`, тіло після нормалізації (структурний diff
   розпарсених JSON — семантика `diff_report`/`--check` із T03). Будь-яка
   різниця або статус ≠ 200 → exit **1**; помилка середовища → exit **2**;
   чисто → exit **0**.
6. **Прибирання в `finally` на будь-якому шляху**: `docker rm -f -v` нашого
   контейнера (+ контроль, що він зник), `SIGTERM→kill` бінарника, `rmtree`
   temp-каталогу; на старті додатково видаляються залишкові контейнери
   **нашого** префіксу `api-parity-node-` від попередніх аварійних прогонів.

## Порти і заборонені ресурси

| Ресурс | Використання |
|---|---|
| `127.0.0.1:9122` | тільки тимчасовий Node-контейнер цього скрипта |
| `127.0.0.1:9123` | тільки Rust-бінарник цього скрипта |
| `0.0.0.0:9118` (prod) / `127.0.0.1:9119` (staging) | **ніколи** не биндяться й не проксіються; якщо 9122/9123 зайняті — скрипт відмовляється брати інший порт (exit 2) |
| `/opt/lampa/data`, staging-сховище | скрипт їх не згадує (grep = 0) і не відкриває; «проби» лише read-only `mode=ro` поза скриптом |

**Чому `/opt/lampa/tmp`, а не `tempfile`:** сесійний `/tmp` — приватний
tmpfs, невидимий для dockerd; bind-mount звідти отримував **порожній**
каталог (під час першого дослідного прогону Node-контейнер бачив порожню БД).
Скрипт тому будує все в спільному `/opt/lampa/tmp/api-parity-*` (каталог
створюється лише якщо його нема, і прибирається лише якщо створив його сам
скрипт і він порожній) і видаляє власний каталог у `finally`.

## Санкційовані відхилення та виключення

1. **`device_access` (маршрут 02 `GET /api/admin/devices`) — виключено з
   контракту** (plan §13.3; §4.2: «таблиці логічно ідентичні, крім
   `device_access`» — Node і Rust по-ріншому пишуть auth-метадані: ip,
   user_agent, last_seen_at, token_hash). Статус/`content-type`/`cache-control`
   маршрута 02 усе одно порівнюються; тіло показано як `EXCL` в рядку
   звіту. У цьому прогоні **інформаційний** masked-diff тіла = 0, але він
   не є умовою проходу — саме виключення є контрактною умовою.
2. **`cache-control`**: Node взагалі не шле цей заголовок (0/27 у
   T03-фікстурах); Rust додає `no-store` на маршрутах 15–23 (план §3.6 п.8;
   T08 §5 п.5 — «додано на всі відповіді, у фікстурах немає»). Правило:
   рівність **або** «Node: відсутній → Rust: рівно `no-store`» (санкція,
   9 маршрутів: 15,16,17,18,19,20,21,22,23); будь-яка інша різниця = FAIL
   (напр., якщо Node шле якесь значення, якого нема в Rust — теж FAIL).
3. **Порівнюваний набір** — рівно те, що в контракті: `status`,
   `content-type`, `cache-control`, нормалізоване тіло. Інші заголовки
   (`Date`, `Set-Cookie`, `Connection`, `Keep-Alive`, `Transfer-Encoding`,
   `Content-Length`) не входять у контракт порівняння; R1/R2/R9 усе одно
   застосовуються до нормалізованого представлення відповіді.

## Правила нормалізації R1–R9 (за T03; ті самі функції, той самий код)

| # | Правило | Застосування тут |
|---|---|---|
| R1 | `Date` → `<date>` | нормалізовано (не в порівнюваному наборі) |
| R2 | `Set-Cookie` значення → `<redacted>` (порожнє — незмінне, logout) | нормалізовано (не в порівнюваному наборі) |
| R3 | timestamp-поля (`created_at`, `updated_at`, `last_attempt_at`, `last_seen_at`, `blocked_until`, `first_attempt_at`) числом → `<ts>` | тіла, спрацювало |
| R4 | `ip` → `<ip>` | тіла, спрацювало |
| R5 | settings-рядки з `key=admin_password/admin_token` → `value="***"` | тіла, спрацювало |
| R6 | секретні поля (`admin_password`, `admin_token`, `device_token`, `auth_token`, `password`, `pin`, `totp`, `token`, `session`, `secret`) → `***` | тіла, спрацювало |
| R7 | будь-який 64-hex у тілі → `***` | цього разу не спрацював (64-hex `device_token` уже приховано R6; `admin_token` — не hex) |
| R8 | запит `Cookie` → лише імена кук | значення кук ніколи не друкуються |
| R9 | `Content-Length` перерахований над нормалізованим тілом | спрацювало (Rust шле content-length) |

Фактично спрацювало в прогоні: **R1,R2,R3,R4,R5,R6,R9**.

## Відкриті пункти / обмеження

1. **Залежність від локального стану:** потрібні docker + pinned image
   локально (скрипт не робить pull) і свіжий release-бінарник (скрипт
   fail-closed із підказкою-рецептом, бо господар без тулчейна).
2. **`device_access`:** інформаційний masked-diff маршруту 02 може стати
   ≠0 після змін у writer-логіці — це не впливає на вердикт (виключено
   контрактом); якщо план змінить виключення, повернути assert тіла.
3. **`cache-control`:** санкція дозволяє лише додавання `no-store` з боку
   Rust; коли крос-шаровий no-store-шар (план §3.6 п.8) буде доведено до
   всіх `/api/*`, правило спрацює без змін (напрямок «немає → no-store»).
4. Під час дослідного прогону виявлено і виправлено (у скрипті): сесійний
   `/tmp` невидимий для dockerd → тепер база саме `/opt/lampa/tmp`.
