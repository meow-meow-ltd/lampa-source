## 2. Реалізована семантика (Node parity)

### 2.1 Profiles (`backend/routes/profiles.js`)

`GET /api/profiles/all`: якщо таблиця `profiles` порожня — створюється рівно
один `Main` (`is_main=1`, `icon='l_1'`, `sort_order=1`) в транзакції, далі
читання `ORDER BY is_main DESC, sort_order ASC, id ASC`. Повторний GET не
дублює `Main`. Відповідь: `{"secuses":true,"profiles":[{id,name,icon,main,child,sort}]}`,
`icon` fallback `l_1`, `sort` = `sort_order` (0 для відсутнього).

`POST /api/profiles/create`: `name.trim()` обов'язковий, інакше
`400 {"secuses":false,"text":"Name is required"}`; `icon` — лише рядок, порожній
→ `l_1`; `sort` через `parseInt` (рядок або число), інакше `max(sort_order)+1`;
`is_main=0`, `is_child=0`; відповідь `{"secuses":true,"profile":{...}}` з
`id` з `last_insert_rowid`.

`POST /api/profiles/update`: `id` через `parseInt`, `0`/`NaN` →
`400 {"secuses":false,"text":"Invalid id"}`; патчаться лише «truthy» поля
(`name`/`icon` — непорожні рядки після trim, `child` — **лише** JSON boolean,
`sort` — `parseInt`); порожній патч →
`400 {"secuses":false,"text":"No fields to update"}`; `updated_at` завжди
оновлюється; відповідь `{"secuses":true}` навіть для неіснуючого `id`
(legacy не перевіряє `rows_affected`).

`POST /api/profiles/delete`: той самий контракт `id`; **звичайний**
`DELETE FROM profiles WHERE id=?` без жодного каскаду — у schema v7 немає
foreign keys (`foreign_keys=OFF`), тому `bookmarks`, `profile_settings`,
`timeline_events` лишаються сиротами. Відповідь `{"secuses":true}`.

### 2.2 Profile settings (`backend/routes/profile_settings.js`)

Profile id: `profile` header → `x-profile` header → `body.profile` →
`body.params.profile` (JS truthiness), `parseInt`; `0`/`NaN` →
`400 {"secuses":false,"text":"Missing profile"}`.

`GET` без `?key=` → `{"secuses":true,"value":{key:value,...}}` (усі рядки
профілю; ключі детерміновано відсортовані); `GET ?key=` (непорожній) →
`{"secuses":true,"value":"..."|null}` (відсутній рядок → `null`).
`POST`: `key` тримиться, порожній → `400 "Missing key"`; відсутнє `value` →
`400 "Missing value"`; `value:null` **видаляє** рядок; не-рядкове значення
серіалізується як `JSON.stringify` (`42`→`"42"`, об'єкти/масиви); інакше
upsert `ON CONFLICT(profile_id,key) DO UPDATE` з `updated_at=Date.now()`.
Відповідь `{"secuses":true}`.

### 2.3 Users backup (`backend/routes/backup.js`) — інвертовані назви

`POST /api/users/backup/export` — **запис**: `data` мусить бути непорожнім
рядком (`400 "Missing data"`), валідним JSON (`400 "Invalid JSON"`); текст
зберігається **дослівно** в `settings.backup_latest`
(`INSERT ... ON CONFLICT DO UPDATE SET value=excluded.value, visible=0`);
відповідь `{"secuses":true}`.
`GET /api/users/backup/import` — **читання**: немає рядка / порожній / SQL NULL
/ непарсибельний blob → `data:null`; валідний JSON → `{"secuses":true,"data":<parsed>}`.

### 2.4 Тіло запиту та гігієна помилок

Тіло приймається як JSON-об'єкт або `application/x-www-form-urlencoded`
(legacy body-parser ставить обидва), `Content-Type` ігнорується; form-поля
лишаються рядками (тому `child=true` у form — не boolean, як у Node).
Помилки БД ніколи не віддають SQL/драйверний текст:
`500 {"secuses":false,"error":"database_error"}` (detail — лише в лог), а
fail-closed стан (`DbState::Unavailable`) → `503 {"secuses":false,"error":"db_unavailable"}`
(до handler-а взагалі не доходить через T10-guard, це defence in depth).

## 6. Примітки

* `api/mod.rs` `not_implemented_response()` став dead code після реалізації
  останньої групи маршрутів (файл поза моїм скоупом); капітан видалив helper
  перед фінальним прогіном — фінальний `clippy -D warnings` чистий (0 warnings).
* T03-фікстури зберігають тіло рядком, тому паритет перевіряється точною
  рівністю рядків (сильніше за «normalized diff»); порядок полів відповідей
  заданий serde-структурами в legacy-порядку (`secuses`/`profiles`/`value`/`data`).
* `profile_settings` без `ORDER BY` у Node віддає rowid-порядок; тут ключі
  відсортовані детерміновано, а `serde_json` все одно серіалізує об'єкт за
  ключами — спостережуване тіло збігається з фікстурою.
* Клієнтський `src/**` (frontend) не змінювався.
