## 2. Legacy-семантика, яку збережено

| Маршрут | Legacy-джерело | Поведінка Rust |
|---|---|---|
| `GET /api/settings` | `backend/routes/settings.js` | масив `{key,value,visible}` у порядку таблиці (rowid); `admin_password`/`admin_token` → `"***"`; `visible` — число 0/1 |
| `PUT /api/settings` | там само + план §3.5 | upsert `{key,value}` → `{"success":true}`; `"***"` для секретного ключа не перезаписує значення |
| `DELETE /api/settings/{key}` | там само | ключ = останній сегмент; `{"success":true}` незалежно від `rows_affected` |
| `POST /api/values` | `backend/routes/data.js` | `{keys:[...]}` → об'єкт лише для наявних ключів; `visible=0` → `null`; невалідний/порожній масив → `400 {"error":"Missing or invalid keys parameter"}` |
| `GET /api/value?key=` | там само | видимий ключ → JSON-рядок; невидимий/відсутній → `null`; без `key`/`key=` → `400 {"error":"Missing key parameter"}` |
| `POST /admin/login` | `backend/routes/auth.js`, план §3.5 | plaintext-порівняння (constant-time) з `settings.admin_password`; немає рядка → fallback `'admin'`; успіх → `{"success":true}` + `auth_token=<settings.admin_token>`; невдача → `401 {"success":false}` |
| `POST /admin/logout` | там само | `auth_token=; Path=/; Max-Age=0; HttpOnly` → `{"success":true}` без БД |
| `GET /api/admin/devices` | `backend/routes/admin.js` | `[{id,device_id,ip,user_agent,status,attempts,last_attempt_at,blocked_until,last_seen_at}]`, rowid-порядок, `token_hash` не вибирається |
| `POST /api/admin/device/action` | там само, план §5.4 | `unblock` → `status='pending', attempts=0, blocked_until=NULL`; `revoke` → `status='pending', token_hash=NULL`; `delete` → видалення рядка; успіх → `{"success":true}`; невідома/відсутня дія → **400 з порожнім тілом** (legacy `writeHead(400); end()`) |

Одруківка `secuses` з §3.6 п.4 належить іншим групам (фікстури 13/14/24);
`settings.js`/`data.js`/`admin.js`/`auth.js` її не містять — тут контракт
`{"success":true/false}` з фікстур 02–08/26–27.

## 3. Свідомі відхилення від Node (зафіксовані в плані)

| # | Відхилення | Причина |
|---|---|---|
| 1 | cookie `auth_token` додає `SameSite=Lax` (і `Secure` лише при `X-Forwarded-Proto: https`); Node віддавав `auth_token=…; Path=/; HttpOnly` | план §3.5 (admin-cookie: `HttpOnly`, `SameSite=Lax`, без `Secure` на LAN) і §5.2; для LAN-HTTP `Secure` заборонений. T03 R2 маскує значення cookie, тому fixture-26/27 звіряються за статусом/тілом, а cookie — за контрактом name/value/Path/HttpOnly/SameSite/no-Secure |
| 2 | DB-помилки → `500 {"error":"internal_error"}`, немає черги → `503 {"error":"database_unavailable"}`; Node віддавав `{error: err.message}` | план §3.6 п.6: сирі SQL-помилки клієнту не віддаємо (свідоме відхилення від legacy) |
| 3 | `PUT /api/settings` — upsert (новий ключ отримує `visible=0`); Node робив лише `UPDATE` | W0-контракт T04 (§3.5 «upsert») |
| 4 | `PUT /api/settings` без рядкового `key`/`value` → `{"success":true}` без запису (legacy `UPDATE` з `NULL` або падав, або зануляв значення) | запобігання втраті даних на malformed-запиті; фікстури не покривають цей edge |
| 5 | `POST /api/values` приймає лише масив рядків; не-рядкові елементи → 400 | opaque-ключі за контрактом — рядки; legacy-поведінка для чисел SQLite нестабільна |
