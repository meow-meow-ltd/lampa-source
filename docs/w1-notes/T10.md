## 2. Реалізована семантика (Node parity)

### 2.1 PIN (`POST /api/pin/verify`, `backend/routes/pin.js`)

Порядок збережено: IP-limit → `device_id` → `TOTP_SECRET` → blocked-device →
TOTP → update. Відповіді:

| Ситуація | HTTP | Тіло |
|---|---|---|
| IP заблокований | `429` + `Retry-After` | `{"ok":false,"error":"too_many_attempts","retry_after":N}` |
| немає `device_id` | `400` | `{"error":"device_id required"}` |
| немає `TOTP_SECRET` | `500` | `{"error":"Server configuration error"}` |
| device `blocked` | `200` | `{"ok":false,"blocked":true}` (без TOTP, **без 403**) |
| успіх | `200` | `{"ok":true,"device_token":"<64 hex>"}` + C-cookies |
| невдача | `200` | `{"ok":false,"attempts_left":N,"blocked":b,"ip_blocked":b[, "retry_after":N]}` |

Кожен успіх: новий `OsRng` 32-byte токен → `hex` (64 lowercase), у БД
`device_access.token_hash = lowercase sha256 hex`; старий токен інвалідується
тим самим `UPDATE`. `status='allowed'`, `attempts=0`, `last_attempt_at=last_seen_at=now`,
`blocked_until=NULL`, `ip`/`user_agent` як у legacy. Успіх чистить `ip_rate_limits`.
5 невдач → `device_access.status='blocked'`; 10 невдач з одного IP → блок 15 хв.

Тіло приймається незалежно від `Content-Type`: JSON, `x-www-form-urlencoded`,
`text/plain` (jQuery/fetch-шляхи). Порядок полів у відповіді — як у Node
(struct-serialization), `retry_after` відсутній, коли блоку немає.

### 2.2 Cookie-модель (D6: C → B)

* PIN успіх ставить **два** cookie з тим самим токеном:
  `lampa_session` (HttpOnly, `SameSite=Lax`, `Max-Age=31536000`) і перехідний
  readable `device_token` (той самий token, **без HttpOnly**).
  `Secure` додається лише коли запит HTTPS (`X-Forwarded-Proto: https`);
  безумовний `Secure`/`SameSite=None` не використовується (S8 §3.1).
* `DEVICE_LEGACY_COOKIE=0` → B-strict: ставиться/приймається лише
  `lampa_session`; default `1` (C).
* `auth_token` (admin) — plaintext legacy, окреме ім'я, не змішується з device.
* На `401` guard додає `Set-Cookie` з `Max-Age=0` для обох device-cookie
  (`auth_token` — для admin-гілки).
* `HttpOnly` на імені `device_token` не ставиться ніколи (B-naive заборонено, S8 §7).

### 2.3 Guard (`http/middleware/mod.rs`)

| Клас | Шляхи | Перевірка |
|---|---|---|
| public | `/api/pin/verify`, `/api/auth/session`, `/admin/login`, `/admin/logout` | без credential |
| admin | `/api/settings*`, `/api/admin/*` | `auth_token` == `settings.admin_token` (constant-time) |
| device | решта `/api/*` | cookie (`lampa_session` → `device_token` у C) → sha256 → `device_access.token_hash` + `status='allowed'` |

* missing → `401 {"error":"token_required"}`; blank/unknown/revoked →
  `401 {"error":"invalid_token"}` (+ cookie clearing); blocked/pending — **401,
  ніколи 403**.
* `DbState::Unavailable` → fail-closed `401 invalid_token` (readiness при цьому
  503); credential-presence перевіряється до БД, тому mount-only тести I0 зелені.
* Автентифікований device вставляється в extensions як
  `AuthenticatedDevice { row_id, device_id }` (для T07/T24); `last_seen_at`
  пишеться не частіше ніж раз на 30 с (перевірка в коді + SQL-guard
  `last_seen_at IS NULL OR <= now - 30 s`).
* Значення cookie/токенів не логуються: лише `path`, `status`, `reason`,
  IP та device_id.

### 2.4 `/api/auth/session`

* валідний device → `200 {"paired":true,"device_id":"…","admin":false|true}`;
  валідний admin без device → `200 {"paired":true,"admin":true}`;
* інакше → `401 {"paired":false,"error":"token_required"|"invalid_token"}`
  (вимога T10; S8 пропонував `200 paired:false` — див. §5);
* legacy `device_token` перевидається як HttpOnly `lampa_session` **тим самим**
  значенням (без ротації, no-re-pair); readable legacy не видаляється;
* `Cache-Control: no-store` на **обох** гілках — `200` і `401` (G2-04: раніше
  `unauthorized()` заголовок не ставив; тепер `no_store()` застосовується до
  кожної session-відповіді, значення те саме — `no-store`);
* `last_seen_at` endpoint **не** пише (S8 §8.3).

### 2.5 TOTP

SHA-1, 6 цифр, 30 с, `window=1`; `TOTP_SECRET` — base32 (lowercase/padding
приймаються). `verify` перевіряє всі 3 кроки без early-exit і порівнює
constant-time; довжина/цифри перевіряються до циклу. Порожній secret → server
config error. `TOTP::new_unchecked` використано свідомо: speakeasy (legacy)
приймає будь-яку довжину base32, зокрема 80-бітний S8-секрет
`JBSWY3DPEHPK3PXP`; тому 128-бітний мінімум RFC не енфорситься (паритет).

### 2.6 Media-auth hook

`auth::media::authorize(Option<MediaSubject>) -> MediaDecision`:
`None` → `Deny(Unauthenticated)`, `status != allowed` → `Deny(Revoked)`,
`allowed` → `Allow { device_id }`. `AuthService::authorize_media(cookie, now)`
зв'язує cookie-резолюцію з політикою для W3/T24; у W1 маршрути медіа ще не
існують, тому модуль під `#[allow(dead_code)]` і покритий unit-тестами.

## 5. Відхилення / ризики / передача далі

1. **`/api/auth/session` при відсутності пари повертає 401**, а не S8-варіант
   `200 {"paired":false}` — так вимагає acceptance T10. Наслідок для T12:
   патч-клієнт має трактувати 401 як «не спарено» (fetch не проходить через
   legacy 401-reload-обробник), інакше можливий reload-loop. Зафіксувати в T12/T14.
2. **Trusted proxy:** CF/XFF приймаються лише від loopback/RFC1918/link-local/
   IPv6-ULA peer (docker bridge, cloudflared, LAN/Tailscale); публічний peer
   завжди ключується власною адресою. Це реалізація plan §5.5 без окремого
   env-списку `TRUSTED_PROXIES` — на P0 достатньо, P1 може зробити конфігурованим.
3. **`ip_rate_limits` anchor:** на відміну від legacy (який у `UPDATE`-гілці не
   оновлював `first_attempt_at`), нове вікно стартує з поточного часу. Це
   виправляє втрату свіжого вікна після expiry; семантика «10/15 хв» збережена.
4. **TOTP 128-bit minimum не енфорситься** (speakeasy parity, S8 80-bit secret);
   порожній secret відкидається. Прод-секрет лишається відповідальністю env.
5. **`last_seen_at`**: throttle 30 с застосовано в guard-шляху; session-endpoint
   не пише взагалі (S8). Медіа-запити W3 отримають той самий throttle через
   `AuthService::authenticate_device`.
6. **Media-auth** поки не підключений до маршрутів (їх немає до W3/T24);
   policy + bridge готові й unit-tested.
7. **Немає періодичного cleanup `ip_rate_limits`** (legacy чистив раз на годину):
   прострочені рядки видаляються ліниво при `check`; на P0 обсяг мізерний.
8. **E2E браузерна матриця S8** (Safari/TV, реальні cookie-jar) — T14; тут
   перевірено реальний HTTP-бінарник, cookie-заголовки та БД-стан.
